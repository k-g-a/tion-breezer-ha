# Перенос действующей установки

[English](development-and-migration.md)

Если этот форк уже работает под доменом `ha_tion_btle`, его можно оставить на ветке `maintenance/ha_tion_btle`. Установка нового компонента рядом со старым сама по себе устройства не переносит. При переносе по инструкции ниже сохраняются записи интеграции, настройки, идентификаторы устройств и сущностей. Повторное сопряжение и изменения в BlueZ не нужны.

## Перенос всех бризеров за один раз

В интерфейсе Home Assistant нет поддерживаемой операции переименования домена пользовательской интеграции. Утилита проекта готовит копии внутренних реестров. По возможности проверьте результат на восстановленной тестовой копии. До начала переноса под новым доменом не должно быть настроенных устройств или записей интеграции.

1. Создайте и скачайте полную резервную копию HA. Сохраните старый компонент и его версию. Скопируйте новый в `/config/custom_components/tion_breezer_2026`. Пока не добавляйте его через «Устройства и службы».
2. Остановите Core (`ha core stop` на HAOS). При подключении к хосту HAOS по SSH на порт 22222 каталог конфигурации обычно находится в `/mnt/data/supervisor/homeassistant`. Из его подкаталога `.storage` скопируйте **core.config_entries**, **core.entity_registry** и **core.device_registry** в закрытый каталог `original` на Linux с Python 3.10+. В этих файлах есть учётные данные других интеграций. Оставьте Core остановленным до завершения записи всех трёх файлов.
3. Из каталога новой версии запустите утилиту на копиях. Первая команда выводит только количество записей. Для четырёх настроенных бризеров ожидается четыре записи интеграции. При конфликте или неожиданном количестве верните исходные файлы и запустите Core.

   ```sh
   python3 tools/migrate_registries.py original
   python3 tools/migrate_registries.py original --output migrated
   ```

4. Локально сравните файлы. Меняются домен записи интеграции, платформа сущности и пространство имён идентификатора Tion, в том числе у соответствующих удалённых записей. ID записей, устройств и сущностей, настройки, имена и MAC-адреса должны сохраниться. Форматирование JSON может отличаться. Замените три файла их копиями из `migrated`, сохранив владельца и права. При ошибке копирования **до запуска Core верните все три оригинала**.
5. Запустите Core (`ha core start`). Проверьте все четыре записи, имена, настройки, устройства, ID и историю сущностей, управление вентилятором, температуру и Boost. В автоматизациях, сценариях и панелях замените `ha_tion_btle.set_air_source` на `tion_breezer_2026.set_air_source`. Обновите фильтры с явным доменом интеграции. Стандартные действия fan и climate могут обращаться к прежним ID.
6. Для отката остановите Core, верните все три оригинала, старый компонент и ссылки на старое действие. Затем запустите Core. Если после снимка менялись другие настройки, восстановите полную резервную копию. Каждый бризер должен обслуживаться только одной интеграцией.

Преобразование проверено на тестовых данных. Проверка на реальных реестрах и на оборудовании с переименованной интеграцией остаётся за владельцем установки.
